# 扫描 PDF 添加文字层：实施方案与计划

日期：2026-10-16。目标代码库：`<PROJECT_ROOT>`。

补充核对：2026-10-20，已检查当前《纳米材料》268页扫描教材及现有选段提问链路，见第13节。

状态：实施计划，尚未开发此功能。本文中的新模块、接口和界面均为拟议设计。

## 1. 目标与完成后的使用方式

在沉浸式阅读中打开扫描 PDF，点击“更多 → 添加文字层”，选择全书或 PDF 页码范围，启动本地 OCR。页面展示真实进度，支持取消、失败后续跑；结束后可下载 OCR 版 PDF，也可直接在沉浸式阅读中打开该副本。

默认保留原文件及原阅读资料，输出新的 PDF。只添加不可见文字，不把扫描页重绘成新的页面图像。生成后的文字支持选择、复制、搜索，并可作为阅读器选段提问和文字批注的依据。

OCR 是确定性的文档处理任务，不依赖聊天历史、LLM 推理轮数、API Key，也不通过聊天 `exec` 执行整书处理。

首版覆盖普通未加密 PDF、中文和英文印刷文字、本地 CPU、全书与指定页范围。公式和表格保持视觉外观，但不承诺公式语义识别或表格结构重建。加密、损坏或无法可靠处理的文件在预检时明确提示。

## 3. 首版范围与明确边界

必须包含：

1. 扫描页预检、依赖检查和页范围校验。
2. 不可见文字写入、坐标对齐、保留页面与原始图像。
3. 后台长任务、持久进度、取消、异常中断恢复、重复提交去重。
4. 页面失败清单与单页重试。
5. 结果下载和“打开 OCR 副本”。
6. 原始文件、书签和原阅读状态保护。

首版不包含：云 OCR、多机分布式执行、公式转 LaTeX、表格转 Excel、自动修复知识库索引、自动替换原资料的历史引用。后台默认一次只运行一个 OCR 任务。

指定页范围指 PDF 阅读器页码，按1起算，不推测书上印刷页码。只给选中页添加文字，输出 PDF 仍保留原书所有页及页序，防止阅读定位地址改变。

## 4. 架构与任务流程

处理链路：

```text
阅读器“添加文字层”
  → 预检与创建任务 API，立即返回 job_id
  → 工作区内持久任务存储
  → OCR 调度器取得任务租约
  → 独立 Python worker，本地加载一次识别引擎
  → 每页识别结果与检查点落盘
  → 从原始 PDF 打开副本，写入所有目标页的文字层
  → 结果校验并原子发布
  → 下载 / 在阅读器中打开 OCR 副本
```

后台 worker 不占用 FastAPI 事件循环，不采用仅存于内存的 `BackgroundTasks` 承载整书任务。浏览器关闭或聊天结束不取消已提交任务。

首版进度使用轮询，运行时约每2秒读取一次任务状态；完成或离开相关页面后停止轮询。断线后重新读取持久状态即可，不把 WebSocket 断线当成 OCR 失败。SSE 可作为后续优化。

### 4.1 状态机

```text
queued → preflight → running → assembling → verifying → completed
                       ↓           ↓           ↓
                   cancelling → cancelled
                       ↓
                    failed

应用或 worker 异常退出：活动任务 → interrupted
手动续跑：failed / cancelled / interrupted → queued
```

`completed` 表示所请求页范围已全部通过验证并发布结果。页面失败不会被计入成功；即使生成了可打开的文件，也不能因此隐藏 OCR 失败页。

应用正常关闭时先停止领取任务，再终止所属 OCR worker 并记录检查点。重新启动后核对租约、进程身份和心跳；遗留任务标为 `interrupted`，由用户点击“继续”，不静默重启整书计算。多 API worker 通过持久租约保证一个任务只有一个执行者。

并发限制按本地 DeepTutor 实例统一执行，不能每个 API worker 各自启动一个任务。运行时目录下的共享调度租约记录已占用的运行槽，私有任务详情仍留在各自的阅读存储中。

### 4.2 取消与续跑

- 取消立即写入任务状态；worker 在页边界配合退出。
- 如果正在执行的本地推理未及时返回，宽限5秒后终止该任务的独立进程；必要时再强制结束，目标10秒内停止。只处理被本任务管理的进程。
- 取消保留已验证的逐页结果，不发布“成功完成”的最终文件。
- 续跑先核对源文件哈希、引擎与模型版本、DPI、页范围和文字定位算法版本。完全一致时复用已完成页，参数变化时新建任务。
- 不允许取消旧任务的请求影响另一任务，也不通过重启 DeepTutor 来取消 OCR。

## 5. OCR 与 PDF 内核设计

### 5.1 引擎与安装

优先采用已有样本验证过的 RapidOCR CPU 路线，通过适配层封装，并将所需包列入可选依赖 `.[pdf-ocr]`。开发时根据当前 Python 3.11 / Windows / ONNX 环境验证兼容版本后锁定依赖范围。

安装和模型准备单独进行；创建任务时只检查可用性。缺少依赖时展示清楚的准备提示，用户确认安装后再下载；不在每次点击开始时重复安装或从聊天目录导入库。

默认200 DPI，支持用户选择300 DPI。引擎每个 worker 只初始化一次，逐页处理图像，处理结束释放内存。ONNX 推理置于独立进程，避免与主进程中的向量索引库争用或冲突。

### 5.2 扫描页判断

结合现有文字的覆盖范围、可用字符、图像覆盖率和正文区域，判断该页是否需要 OCR；不能只用“少于100字符”判断整页。

- 正文已有完整可用文字层：复制保留，不重复添加。
- 只有页码、水印等局部文字：识别正文，避免重复写入已有文字区域。
- 空白页：记录为空白跳过，不列为失败。
- 已有质量不明的 OCR 层：首版给出明确提示，避免直接叠加第二套文字；重做旧 OCR 层另行实现。

### 5.3 文字框对齐

必须处理坐标转换和字体度量：

1. 将 OCR 像素四角坐标通过渲染变换的逆变换，转换到 PDF 页面坐标；测试页面旋转、CropBox 和非零页面原点。
2. 根据实际字体的文字宽度、上升部和下降部，计算字号、基线及横向缩放。
3. 缩放以 OCR 框为依据，不使用可能导致长行再次溢出的固定最小横向比例。
4. 保留完整识别字符串；无法正常放置的文字框记录为定位问题，不通过裁掉文字掩盖问题。
5. 写入不可见文字，保留正确的 Unicode 映射。
6. 对多栏、图题和表格行进行阅读顺序处理；不把全页按同一纵坐标机械拼接。

每页记录识别框、文字、置信度、文字定位参数及验证结果，后续可以调整排版算法而不必再次识别图像。OCR 置信度用于诊断，不直接冒充识别准确率。

### 5.4 写出 PDF

最终写出时从完整原 PDF 打开文档，只向目标页追加隐藏文字，再保存到新的临时结果文件。避免逐页拼接导致跨页链接和目录丢失。

保存后重新打开并验证页面数、页面尺寸、旋转、目录、可用链接和原有 PDF 批注。验证通过后才以原子文件替换方式发布结果文件。中途退出只留下未发布临时文件，不污染原文件或已有成品。

处理中不将原页扫描图重新编码为低质量图片。字体嵌入、子集化和去重以实测兼容性为准，不预先承诺输出体积只增加固定百分比。

## 6. 存储、配置与访问边界

沿用当前用户和内容工作区解析，使用 `ReadingStore.root` 下的 `_ocr/` 存放 OCR 任务数据库和工作目录。不要把输出放回关联资料文件夹或知识库的 `raw/`、`visual_assets/`，避免再次被文件夹同步扫描。

如果阅读存储实际位于关联目录下的 `.deeptutor/` 内，单纯换一个子目录仍会被递归同步。因此需要同时核实并修复关联文件夹扫描的排除规则：忽略 `.deeptutor/` 和已经解析出的 DeepTutor 管理目录。只排除系统管理数据，不排除用户普通资料目录；不自动解除关联或启动同步。

拟议目录：

```text
<ReadingStore.root>/_ocr/
  jobs.sqlite3
  jobs/<job_id>/
    specification.json
    pages/000083.json
    events.jsonl
    result.pdf
    verification.json
```

任务数据库包含：owner、内容工作区作用域、material_id、源文件完整 SHA-256、引擎/模型/定位算法版本、参数、状态、页状态、当前阶段、心跳、租约、错误、结果路径、结果哈希和派生资料 ID。阅读资料集 ID 与内容工作区 ID 分开命名，避免混淆。

页面状态仅在对应结果文件原子写入并校验后更新为完成；崩溃在两次写入之间时，重启通过哈希和文件完整性重新对账。

前端只提交已导入资料的 material_id 和处理选项。源文件路径由服务端从 `ReadingStore` 解析，接口不接受任意宿主文件路径。任务状态、日志、下载和取消都验证当前用户、工作区及资料访问权限。

设置拟加入运行时设置服务，使用 `data/user/settings/pdf_ocr.json`，包含 DPI、并发数、模型位置及缓存清理策略；已有设置缺少新文件时采用默认值，不改变模型提供商或其他功能设置。

检查磁盘空间、源文件可读性及原文件哈希。临时图像只在内存中保留当前页，默认不保存扫描页截图；用户清理 OCR 中间结果时，不删除已导入资料仍引用的最终 PDF。

考虑到此前已清理教材缓存图片，OCR 副本导入时增加仅提取文字、图片按需渲染的模式，避免沿用默认资料提取流程又批量生成教材图片缓存。PDF 内部的扫描图像仍保留，阅读和必要的图片提问从 PDF 按页或区域读取。

## 7. 拟议 API

以下路由以现有 reading 路由前缀为基础，具体 OpenAPI 类型随实现生成：

- `GET /materials/{material_id}/ocr-preflight`：PDF 是否可处理、引擎是否就绪、页数及当前任务。
- `POST /materials/{material_id}/ocr-jobs`：提交选项并创建任务，返回202及 job_id；重复提交返回已有任务。
- `GET /materials/{material_id}/ocr-jobs/{job_id}`：状态、逐页计数、失败页、阶段和 ETA。
- `POST /materials/{material_id}/ocr-jobs/{job_id}/cancel`：请求取消，重复请求幂等。
- `POST /materials/{material_id}/ocr-jobs/{job_id}/resume`：核验参数后继续未完成或失败页。
- `GET /materials/{material_id}/ocr-jobs/{job_id}/result`：仅发布完成的 PDF；支持下载和 Range 请求。
- `POST /materials/{material_id}/ocr-jobs/{job_id}/material`：幂等创建 OCR 派生阅读资料，返回可打开的资料 ID。

重试和取消需要进行状态转换校验。运行中的任务不重复执行；未完成的结果不伪装成成功文件下载。源资料被删除或变更后，任务不能发布到另一份资料上。

## 8. 界面与阅读器联动

入口加入 `ReaderPane` 注册的资料菜单，仅当前资料为 PDF 时显示“添加文字层”。

设置对话框提供：全书/当前页/自选范围、200/300 DPI、检查结果、保存为副本说明和“开始”。页范围包含越界、倒序、重复或不合法输入时立即提示。

任务区域显示：阶段、已检查页数、OCR成功页数、已有文字跳过页数、空白页、失败页、耗时、最近活动和预计剩余时间。ETA 使用实际页耗时滚动估算，预热阶段不显示虚假的精确时间。状态文字使用现有 i18n 机制。

运行时可取消；取消或中断后可继续；失败时可查看具体页号和原因。已提交的任务重新进入该资料时仍可看到。

完成后提供“下载 OCR PDF”和“打开 OCR 副本”。后者通过阅读资料目录和存储服务导入结果，并加入当前资料集；用户点击后切换到副本，保留当前页位置。

原始 PDF 和原资料 ID 保持不变。DeepTutor 自身的旧批注仍属于原资料，首版不自动搬迁文字偏移选择器；PDF 内嵌批注则由副本保存流程保留。旧聊天引用继续指向原资料，新选段提问基于当前打开的 OCR 副本。

知识库索引属于独立任务，OCR 完成不触发自动重建、同步关联目录或恢复此前取消的知识库任务。

## 10. 分阶段实施与每阶段验收

### M1：独立 OCR 内核与样本验证

落实引擎适配、坐标转换、文字框缩放、字体和完整 PDF 副本写出。

验收：第83页、第101页和一张真实表格页；另外构造旋转页、裁剪页、长行与中英混排测试。旧演示两行越界问题得到验证修复。中文可搜索、整行复制完整，144 DPI 样本外观比对无变化。

M1 不通过，不进入整书运行。

### M2：持久后台任务

实现 SQLite 状态、页面检查点、独立 worker、租约、进度、取消及恢复。

验收：10页任务可从中断点继续；取消无需停止 DeepTutor；强制结束 worker 后已完成页不重复 OCR；损坏的检查点触发重新处理而不是误报成功。

### M3：API、作用域与依赖准备

注册预检、创建、查看、取消、续跑、下载与派生资料接口，生成契约。

验收：重复提交不启动两份任务；跨用户或工作区无法访问结果；缺依赖有明确提示；失败/取消状态没有可误认成成功的结果。所有读状态接口不启动处理。

### M4：前端可用闭环

加入菜单、设置对话框、任务面板和刷新后恢复。

验收：从“添加文字层”到下载 PDF 的流程无需给聊天 AI 发指令；关闭聊天、刷新网页不丢任务；阶段与错误说明清楚；移动端和深色模式可用。

### M5：阅读器联动与兼容性

加入“打开 OCR 副本”，验证资料集、页码、选择、复制、搜索和选段提问链路。

验收：PDF.js 展示副本自己的文字层；AI 的当前资料和引用页码来自副本；原文件哈希不变，旧资料的批注、位置和引用保留；PDF 内嵌目录及可用链接得到验证。

### M6：真实教材全书验收与交付

交付：功能代码、安装说明、测试结果、真实 OCR PDF、质量报告和已知限制。保留可回退的原文件与现有应用设置。

建议分成三个可运行交付：M1–M2 为后端处理核心；M3–M5 为应用内完整功能；M6 为这本教材的最终验收。开发耗时需要在 M1 验证坐标及引擎兼容后估算；全书运行时间根据实测10页速率估算，不把单页结果直接当成保证。

浏览器验收实际选中并复制中文、搜索命中、发送选段提问。最终视觉检查不能仅靠“能提取文字”替代。OCR 文本允许模型识别误差，但必须公开低质量或失败页，不能以置信度宣称全书95%以上准确率。

## 12. 完成定义

只有满足以下条件，才能宣布功能已加入 DeepTutor：

- 新入口、接口和后台服务已经运行在用户访问的本地实例中。

## 13. 《纳米材料》扫描教材适配确认（2026-10-20）

此次为只读核对，没有启动 OCR、创建新的教材 PDF 或修改原书。

### 实际文件

- 当前阅读资料：`纳米材料.pdf`，material_id 已脱敏。
- PDF 共268页，约111.1 MiB，与截图页数一致。
- 抽查第1、16、50、100、200、268页，均有一张扫描图，可提取文字数均为0。
- 不能仅据六个抽查页断言全书每页都没有文字；正式任务仍逐页预检。

### 与侧边栏提问的衔接

现有 `PdfPage.tsx` 能渲染 PDF 已有文字层。`ReaderPane.tsx` 的 `askAboutSelection` 将选中文字和 locator 放入 `dt:reader-ask` 事件；`ReadingWorkspace.tsx` 接收后显示选段并打开侧边栏，`ReadingComposer.tsx` 提交时携带该阅读位置与选段。

因此不必重新开发一套侧边栏。需要交付的闭环是：识别扫描图中的文字 → 按正确位置写回不可见文字层 → 导入 OCR 副本并提取其页面文字 → 激活副本 → 用现有选段提问流程提交。

只把识别结果放入聊天、Markdown 或知识库，不会让原扫描 PDF 变得可选；只切换浏览器显示文件而不更新当前资料与后端页面文字，也不算接通闭环。选段问答本身不以重新建立知识库索引为前提。

### 此教材的样本验收

首轮使用截图所在第16页、一页连续正文、一页表格或公式密集页。至少完成：

1. 第16页正文和图注可分别选中；多行复制保持基本阅读顺序，选区不偏离原文。
2. 搜索 OCR 实际识别出的关键词能定位到相应文字；原扫描页面外观保持一致。
3. 选择一段正文并点击提问，侧边栏显示同一段文字，引用页码为PDF第16页；提交时实际携带 OCR 副本的资料身份及文字内容。
4. 切换资料、刷新页面后仍然基于 OCR 副本工作，原扫描件和原资料保留。

小字号图注可用300 DPI与200 DPI做样本比较后确定参数。化学式、上下标和图中的字母可能识别错误，应作为明确的质量边界；结构示意图本身不属于可通过文字层选中的正文，图像理解使用截图或区域图片提问路径。

结论：现有实施方案在技术路径上适用于这本教材；是否达到可用标准，仍以新增功能实施后的样本与浏览器端到端验收为准。
