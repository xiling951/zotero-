# Zotero 扫描 PDF 文字层与 AI 选段提问：实施方案

日期：2026-10-20。目标：当前 `<PROJECT_ROOT>/Zotero` 安装与本机插件。

状态：实施方案，尚未开发或安装本方案中的 OCR 功能。本次只读核对现状并撰写文档，没有转换教材、修改原 PDF、安装插件或调整模型账号。

参考文件：[DeepTutor 原实施计划](pdf-text-layer-implementation-plan.zh-CN.md)。本文以 Zotero 为交付主体，不以改造 DeepTutor 网页阅读器为前置条件。

## 1. 结论与推荐路线

原计划可以借鉴，主要可复用的是 OCR 内核设计、隐藏文字定位、逐页检查点、取消续跑和结果验收。不能直接搬用的是 DeepTutor 的阅读资料身份、FastAPI 路由、React 界面和工作区权限机制。

推荐新增一个独立的“PDF 文字层”Zotero 插件，配合独立本地 OCR 服务；对现有 AI Sidebar 只增加必要的附件身份与选区衔接。使用 RapidOCR 的 CPU 路线开展样本验证，不要求提供模型 API Key，不通过聊天指令执行长任务，不依赖 MinerU 的在线解析。

完整用户流程：

```text
在 Zotero 选择扫描 PDF
  → 右键“添加文字层…”
  → 选择当前页、页范围或全书
  → 本机后台 OCR，可查看进度、取消和继续
  → 校验通过后，在同一文献条目下添加 OCR 副本
  → 点击“打开 OCR 副本”，定位到原阅读页
  → 选中文字，交给现有 AI 侧边栏解释、翻译或整理笔记
```

默认保留扫描页面的可见内容、所有页面及其顺序，只追加不可见文字。原文件、原附件、旧批注和旧聊天记录保留。

不建议把此功能塞进 PDF2zh 翻译流程。当前 PDF2zh 已有公式排版保护，OCR 的目的、验收方法和任务生命周期与翻译不同，应独立安装、独立更新、独立回退。

## 2. 本次核对到的项目基线

### 2.1 已确认的本地事实

- Zotero 可执行文件版本为 **10.0.6**。
- `profile/extensions.json` 登记启用四个插件：AI Sidebar **0.8.18**、PDF2zh **4.1.7**、Translate for Zotero **2.4.8**、AI 侧栏深色模式 **1.0.2**。
- 当前没有安装专门的 Zotero OCR 插件；现有 PDF2zh Python 环境也未发现 RapidOCR、OCRmyPDF 或 PaddleOCR 包。
- AI Sidebar 已有 `registerReaderSelectionCapture()`、`getSelectedTextForPrompt()` 等选区处理逻辑，使用 `renderTextSelectionPopup` 事件，并读取当前 Reader 的选区。
- MinerU 结果由 `saveMineruCache()` 保存为 Markdown、内容清单及图片资产；这条链路没有把隐藏文字写回原 PDF。
- `tools/sidebar-pdf-volumes.js` 与 `tools/split_pdf.py` 提供了本机处理 PDF、通过 Zotero API 导入同条目子附件及记录来源关系的参考代码。
- 本地 PDF2zh 服务的 `/health` 返回 `layoutSafety=bitmap-formula-protection-v1`，现有公式保护仍在运行。
- `Start-Zotero.ps1` 目前负责启动 8890 翻译服务及本安装的 Zotero，可参考其隐藏启动方式，但 OCR 使用自己的环境与服务。

上述事实来自当前安装文件、插件清单、已打包脚本和健康接口；不等同于 OCR 功能已经通过运行验收。

## 3. 原计划如何迁移

### 3.1 直接保留的设计原则

1. OCR 是独立文档处理，不调用聊天模型，不依赖聊天会话是否存在。
2. 独立 worker 逐页处理，识别引擎每个 worker 初始化一次，逐页结果原子落盘。
3. 由 OCR 框反算 PDF 坐标，处理旋转、CropBox、非零原点、字体度量和横向缩放。
4. 保存新副本，原文件不覆盖；从完整 PDF 追加文字，避免重新拼页破坏目录与链接。
5. 指定页范围也保留全书页数和页序，范围外页面原样保留。
6. 明确区分失败、空白跳过、已有文字跳过与成功，支持取消、中断恢复和失败页重试。
7. 文字可提取不等于可用，必须验证页面外观、真实选区、复制、搜索和问答请求。

原计划第 83 页原型曾存在两行隐藏文字越界，后续改动尚无完整验收证据。可以借鉴算法思路，不能将该原型直接作为合格生产内核。

### 3.2 替换为 Zotero 的机制

- `material_id` → 当前配置目录范围内的 `libraryID + attachmentKey + sourceSha256`；条目数字 ID 只作本机快速定位，不作为跨配置目录的稳定身份。
- DeepTutor 阅读菜单 → Zotero PDF 附件右键菜单、工具菜单、可选的阅读器工具栏入口。
- React 任务面板 → 插件提供的 Zotero 窗口或面板，复用已有主题习惯，支持深浅色。
- `ReadingStore` → 独立 OCR 任务库与附件来源登记。
- “导入派生阅读资料” → 通过 Zotero 附件 API 导入同一父文献下的 OCR 子附件。
- 浏览器选段事件 → Zotero Reader 的文字层与现有 AI Sidebar 选区捕获链路。
- Web 多用户权限 → 本机配置目录隔离、文献库权限、插件与本地服务认证。

不迁移 DeepTutor 的资料集、关联文件夹扫描、知识库自动索引或生产前端构建逻辑。将来如需同时改造 DeepTutor，再单独接入同一独立 OCR 内核。

## 4. 首版范围与使用边界

首版支持本机 Windows、中文及英文印刷文字、CPU 推理、普通未加密 PDF、全书和指定 PDF 页码范围。页码按阅读器页面序号从 1 起算，不推测书内印刷页码。

必须交付：预检、依赖准备、文字层生成、持久任务、取消、继续、失败页重试、验收报告、同条目导入、打开副本，以及 AI 选段提问闭环。

首版不实现公式转 LaTeX、表格结构重建、自动纠正教材内容、旧 OCR 层自动移除、Zotero 数据库批注迁移、跨设备任务续跑或 OCR 任务本身的云同步。

本地 OCR 不受 MinerU 单文件 200 页限制。268 页教材可以本地整书处理；若用户另需在线 MinerU 全书解析，应单独走已验收的分卷功能。这两项操作互不作为前置条件。

图中的分子结构、曲线和照片不会因为加文字层变成可选文字；它们使用图片或区域提问。公式、上下标和化学式可能识别不准，页面图像仍作为核查依据。

## 5. 推荐架构与接入方式

### 5.1 三层分工

```text
Zotero PDF 文字层插件（新建独立 XPI）
  ├─ 菜单、设置、预检、进度、取消/继续
  ├─ 解析当前附件、文献库权限、源文件校验
  ├─ 导入 OCR 副本、来源关系、打开并定位
  └─ 向 AI Sidebar 提供显式派生附件信息
                    ↓ 本机认证连接
OCR 任务服务（独立 Python 环境）
  ├─ SQLite 状态、单运行槽、进程监督、心跳
  ├─ 任务去重、取消、恢复、结果发布
  └─ 只访问本服务管理的输入、检查点与结果
                    ↓ 固定模块入口
OCR worker 与 PDF 内核
  ├─ 扫描页分类、RapidOCR CPU 识别
  ├─ 隐藏文字定位、Unicode 与阅读顺序
  └─ 页面/结构/文字几何验收
```

服务不读取或写入 `zotero.sqlite`。所有条目、附件与索引相关操作经运行中的 Zotero API 完成；不能从 Python 绕过 Zotero 写数据库。

### 5.2 为什么采用独立插件与服务

独立插件让文字层功能可以单独停用、更新和回退；停用 AI Sidebar 后仍能生成可搜索 PDF。只有选区问答依赖现有 AI Sidebar。

独立 OCR 环境避免改变 PDF2zh 已锁定的 PyMuPDF/BabelDOC 组合，也避免将 ONNX 依赖加入 DeepTutor 主进程。服务默认仅一个 OCR worker；与翻译同时运行时限制 CPU 线程，并在样本阶段测量资源竞争。

OCR 服务采用只监听 `127.0.0.1` 的独立端点，端口由启动时分配并通过配置目录对应的运行记录发现，不占用或修改 PDF2zh 的 8890 端口。

### 5.3 与现成 Zotero OCR 插件的关系

[Zotero OCR](https://github.com/UB-Mannheim/zotero-ocr) 已提供调用 Tesseract、生成 OCR PDF 并导入父条目下的流程，可参考其菜单、配置和附件导入实现。它可作为基础可用性的对照，但其标准功能不能直接证明本方案要求的断点续跑、严格版面验收和 AI 附件身份衔接均已具备。

首版只交付一套主流程，不要求用户同时安装两套 OCR 插件。若 M1 证明 RapidOCR 无法达到中文样本标准，再通过同一引擎适配层评估 Tesseract，不能在任务中途无记录地更换识别模型。

## 6. 任务、文件和生命周期

### 6.1 任务状态与导入状态分开

```text
queued → preflight → running → assembling → verifying → ready
                         ↓                    ↓
                     cancelling            failed
                         ↓
                     cancelled

服务/worker 异常退出 → interrupted
failed / cancelled / interrupted → 用户选择继续 → queued

结果导入状态：not_imported → importing → imported
                               ↓
                           import_failed
```

`ready` 表示请求范围的文字层结果全部通过检查；`imported` 表示已成功进入 Zotero。导入失败时保留合格 PDF，允许重试导入，不重新跑整书 OCR。Zotero 退出时任务可以继续；下次打开后查询持久任务并完成导入。OCR 服务自身退出则停止领取任务、保存检查点并终止其所属 worker。

禁止用只有内存字典或 UI 的进度窗口承载整书任务。参考分卷工具的导入方式，不照搬其短任务生命周期。

### 6.2 逐页检查点与取消

- 页结果包含识别框、完整文字、置信度、坐标变换、放置参数、识别及验证版本与哈希；原子写入成功后才更新页状态。
- 取消立即持久化；worker 在页边界退出。推理无响应时，宽限后只结束本任务登记的进程树，目标在 10 秒内停止；实际能力在 M2 验收。
- 中断保留已验证结果；续跑匹配源文件、引擎、模型、DPI、页范围、坐标算法和写入版本。参数不匹配则新建任务。
- 一个配置目录同一任务只允许一个执行者；服务与 SQLite 租约避免多个 Zotero 窗口重复启动。
- 源附件删除、移库、失去编辑权限或文件内容变化后，不自动导入到其他附件或父条目下。

### 6.3 输入快照、去重与容量

任务开始时流式计算源文件 SHA-256，插件将可读原件复制为服务管理的输入快照。快照保证原文件被外部修改时不会造成前后页来自不同版本；复制前后核对哈希，导入前再次核对原附件身份及源文件哈希。

任务指纹至少包含配置目录标识、文献库、附件 key、源 SHA-256、页范围、DPI、引擎/模型/定位版本。并发重复提交返回同一任务；显式更换参数则保留为不同版本。

容量预检同时考虑输入快照、输出、临时保存和 Zotero 最终附件副本，不承诺固定增量百分比。仅保留当前页渲染图于内存，默认不输出整书截图。失败和取消时可清理输入快照，但应明确因此无法离线续跑。

## 7. OCR 与不可见文字内核

### 7.1 依赖与模型准备

优先评估 [RapidOCR 的 ONNX Runtime CPU 路线](https://github.com/RapidAI/RapidOCR)。版本不沿用聊天原型的临时包目录；在当前 Windows CPU 上验证 Python、ONNX Runtime、PyMuPDF、NumPy 和模型组合后锁定，记录模型来源、许可证与 SHA-256。

模型下载与环境安装是单独的“准备 OCR 环境”操作。点击开始任务只检查环境，不隐式联网下载、自动升级依赖或调用 pip。完成准备后，识别和写入过程可离线运行。OCR 不需要 OpenAI、DeepSeek、Qwen 或 MinerU 的密钥。

默认先评估 200 DPI，并以 300 DPI 比较小字号图注；最终默认值由第 16 页及其他样本的准确性、位置和耗时决定，不能只按单页速度选择。

### 7.2 逐页分类与混合 PDF

- 综合正文文字覆盖、可用字符、图像覆盖和正文区域判断，不能仅凭字符数阈值决定。
- 已有完整可用原生文字层：保留并跳过 OCR。
- 只有页码、水印等少量文字：识别正文，避免在已有文字区域再次叠加相同文字。
- 空白页：记录“空白跳过”，不报错，不把插图页误当空白页。
- 已有质量不明 OCR 层：提示需单独处理；首版不静默叠加第二套文字。
- 加密、签名或含不支持结构的 PDF：预检说明限制。带数字签名的文件不能承诺追加文字后签名仍有效。

### 7.3 坐标、字体与阅读顺序

1. 保存渲染变换及 OCR 四角框，通过逆变换映射回 PDF 原始坐标；识别前如做旋转纠正，也必须组合逆变换。
2. 覆盖页面旋转、CropBox、MediaBox、非零原点、非标准页面尺寸及带倾斜的扫描。
3. 依据字体宽度、上升/下降部、基线和字符间距放置隐藏文字；按识别框计算横向缩放，不使用会让长行越界的固定下限。
4. 中文正文至少使用能正确嵌入并映射 Unicode 的字体。字体子集化必须经 Zotero Reader 的搜索和复制实测。
5. 保留完整识别字符串，放不下的文字框进入定位失败清单，不裁掉尾字制造“通过”。
6. 多栏、正文、图注及表格行分别处理阅读顺序，不能把同一高度的不同栏直接拼成一句。
7. 同时检查行框与实际字形落点，避免“整行框大致对齐，但拖选某几个字位置明显偏离”。

识别置信度只供诊断；中文复制样本需人工核对。化学式与数学表达不得由 LLM 自动改写并替换原扫描内容。

### 7.4 写出与验收

从完整输入快照打开 PDF，只在目标页追加不可见文字，保存为同卷上的临时结果，重新打开检查后再原子发布。保留原有可见内容和图像，不把全部页面重新编码为扫描图片，不以切栏或重排方式生成 OCR 副本。

每页及整本文档检查：页数、尺寸、旋转、CropBox、页标签、书签、可用内部/外部链接及 PDF 内嵌批注。注意“PDF 内嵌批注”和“Zotero 数据库批注”是两类对象。

视觉检查采用同一渲染器、相同 DPI、同样批注显示设置对比原页与结果。隐藏文字正常情况下不应改变渲染像素；差异不能直接放行，需定位原因。几何报告记录越界、未放置框、重复层和阅读顺序异常，不能只看 `extract_text()` 非空。

已有 `pdf_layout_quality.py` 面向翻译后的可见公式重叠，并主动忽略隐藏文字，不适合作为 OCR 验收器。新建 OCR 专用验证模块，借鉴其报告结构即可。

请求范围内有失败页时不标为 `ready`。若提供调试文件，名称和界面必须标明“未完成”，不得自动作为全书 OCR 成品导入。局部范围全部成功时可以发布，但附件必须注明“局部文字层”，不宣称全书可选。

## 8. Zotero 附件、批注与阅读位置

### 8.1 保存为同条目子附件

插件通过 `Zotero.Attachments.importFromFile()` 等当前版本可用 API 导入普通存储附件，不直接往 `library/storage` 中自行创建伪附件目录。文件路径由 Zotero 管理，不能导入为指向可清理任务目录的链接附件。

父文献、集合和元数据沿用原条目。记录来源附件 key、原件哈希、结果哈希、任务 ID、页范围和处理版本；人类可读的名称与标签只帮助辨认，不作为唯一身份。

建议命名：

- 全书：`纳米材料｜OCR 文字层（完整）`。
- 局部：`纳米材料｜OCR 文字层（PDF 第 16–20 页）`。

即使只处理第 16–20 页，PDF 仍保留所有页面。再次点击导入按任务与结果哈希复用已有附件，避免重复添加。使用 Zotero 来源关系并维护独立派生登记；不向 Zotero 增加未经支持的字段。

独立 PDF 没有父文献时，预检明确提示将新建父条目，保留已有集合关系后再操作。只读文献库、无附件写入权限或尚未下载的云端占位文件，先提示处理条件，不静默改为其他文献库。

### 8.2 旧批注与新批注

[Zotero 官方说明](https://www.zotero.org/support/pdf_reader)指出，内置阅读器的批注存于 Zotero 数据库，并不自动写入 PDF。因此复制原 PDF 不会自动复制这些批注。

首版保留原附件及其所有数据库批注、笔记引用和聊天链接；OCR 副本上的新批注归属新附件。不自动迁移旧批注，也不把旧注释的 `parentItemID` 改成副本。

若以后增加批注复制，必须单独实现附件映射、几何校验、去重与回滚，并处理新 OCR 层文字选择范围不同的问题；不纳入本次首版完成条件。

### 8.3 打开与切换

完成后用户点击“打开 OCR 副本”，插件打开实际新附件，并按相同 PDF 页序定位到原阅读页；跨副本的缩放、滚动位置只在当前版本 API 允许且经验证时恢复，否则保证页码一致。

不关闭原标签、不清空聊天草稿、不修改原附件阅读状态。操作结束后验证当前 Reader 的 attachment key，不能只更改标题或左侧选中条目。

## 9. AI Sidebar 必须补齐的衔接

这一部分是 Zotero 版本相较原 DeepTutor 计划最重要的新增工作。

### 9.1 当前阅读附件优先

一次选段问题明确携带：父文献身份、实际 OCR 附件身份、源附件来源、PDF 页序、原始选区文本及 Reader 选区位置。

条目层级只负责共享书目信息。选区、页码、Reader 文字、OCR 结果和解析缓存必须绑定实际附件，不能仅按父条目共用，也不能将 OCR 副本套用到“中文译文优先回到原文”的规则。

当前 `readerItemIDs()` 同时收集 fallback、附件和父条目 ID，现有选区记忆可能跨这些候选读取。实施时需要明确优先级并验证，不在 OCR 与原扫描件切换时复用旧选区。

### 9.2 选段问答不强制 MinerU

有可用文字层后，直接复用 `renderTextSelectionPopup` → `getSelectedTextForPrompt()` → 本轮消息的链路。选段及附近页面上下文从当前 OCR 附件的 Reader 文字获取；选段问答不以先完成 MinerU 全书解析为条件。

对超长教材，选段优先，按请求补充当前页或邻页，不自动把整本识别文本发送给模型。全文总结可单独等待索引或分段检索，不能把全文解析失败解释成选段无法提问。

如现有侧栏有“未解析则禁用发送”的逻辑，应仅针对确实需要全文解析的动作，而非禁用已有有效选区的提问。

### 9.3 缓存、索引与来源一致

- OCR 源附件和副本使用不同缓存身份；来源哈希、结果哈希和附件 key 一并参与校验。
- 新附件可以通过当前 Zotero 版本支持的全文索引 API 发起索引，索引状态独立展示。索引未完成时，Reader 的选区问答仍可工作。
- 268 页文件的在线 MinerU 限制单独处理，不把 OCR 服务送回 MinerU 识别。
- OCR 导入事件只使相关附件上下文失效，不全局清空聊天、翻译缓存和其他分卷缓存。
- 原附件、新 OCR 副本、局部 OCR 版及各分卷的页码必须分别正确；分卷来源登记原书页码映射，不将分卷页码误报为整书页码。
- 以显式附件来源登记识别派生文件，不能依赖文件名包含“OCR”判断。

## 10. 存储、配置与本机接口

### 10.1 建议目录

以下均为拟议新增路径，实施时从 Zotero 数据目录与安装根目录解析，不将本机绝对路径写死在插件中。

```text
<PROJECT_ROOT>/Zotero/
  tools/pdf-text-layer/          # 新插件可维护源码、构建入口
  ocr/
    service/                    # 任务监督与 HTTP 适配
    core/                       # OCR、文字写入、验证；不依赖 Zotero
    requirements.lock
    runtime/                    # 独立 Python 环境
    models/                     # 锁定版本与哈希的本地模型
  library/zotero-pdf-text-layer/
    jobs.sqlite3
    jobs/<job_id>/
      specification.json
      source.pdf
      pages/000016.json
      events.jsonl
      result.pdf
      verification.json
  downloads/repairs/pdf-text-layer/<release>/
    baseline.json
    test-report.json
    previous-plugins/
```

上面目录不属于 Zotero 自动同步的附件。正式 OCR 成品导入后由 Zotero 管理，能否同步由该文献库原有设置与配额决定；任务、模型和检查点不作为普通附件同步。

服务端口发现文件与认证令牌放在当前 Windows 用户受保护的本地配置目录，按 Zotero 配置目录哈希分隔。若项目盘文件系统不支持 ACL，不将密钥保护寄托于项目盘权限；使用 `%LOCALAPPDATA%` 下的用户配置目录。日志不记录令牌或模型账号密钥。

### 10.2 本机接口边界

以下是拟议契约，命名可在实现时统一，不复用 DeepTutor 的 `/materials` 路由：

- `GET /v1/health`：服务协议、内核与模型就绪状态。
- `POST /v1/sources`：登记插件已复制到受控目录的输入快照，返回 opaque `source_id`。
- `POST /v1/preflight`：按 `source_id` 检查文档与选项，不启动 OCR。
- `POST /v1/jobs`：创建或复用任务，立即返回任务 ID。
- `GET /v1/jobs/{id}`：持久状态、阶段、逐页计数、失败页、心跳与耗时。
- `POST /v1/jobs/{id}/cancel`、`/resume`、`/retry-pages`：幂等且校验状态转换。
- `GET /v1/jobs/{id}/result`：只提供已验证的发布结果及哈希。
- `POST /v1/jobs/{id}/import-receipt`：插件回报 Zotero 导入结果，便于重启后去重。

除最小健康信息外，接口均验证当前配置目录令牌。状态修改拒绝非 JSON 和无认证请求，不对任意网页开放 CORS；核对 Origin/Host，不能仅依靠“监听本机”当作认证。

接口不接受任意宿主 `sourcePath`、输出目录、Python 命令或模型下载 URL。服务只解析自己目录内的快照 ID，检查路径逃逸与符号链接。Zotero 插件负责本机附件权限及导入权限。

### 10.3 清理与卸载

完成导入并校验哈希后可清理任务结果副本及输入快照，保留精简来源登记。结果目录与正式附件目录分离，清理任务不能删除已导入的 Zotero 附件。

停用插件移除菜单、计时器和监听器；停止服务只处理该服务拥有的进程。卸载保留正式 OCR 附件与原附件。设置独立于 AI Sidebar 账号，不改变现有 API Key、联网、翻译或深色设置。

## 11. 界面与反馈

主要入口是 PDF 附件右键“添加文字层…”，另在工具菜单提供“为当前 PDF 添加文字层…”。选中文献父条目且有多个 PDF 时先选择目标附件，不默认拿第一个附件处理。

设置对话框显示目标文件与真实页数、是否扫描件、当前环境是否就绪、全书/当前页/页范围、DPI、输出为副本及已有任务。页范围越界、倒序、非法格式在启动前提示，重复页归一化。

任务面板展示真实阶段、已预检页数、OCR 成功页、已有文字跳过页、空白页、失败页、当前页及最近活动。预热阶段说明正在加载模型；ETA 依实际页耗时估算，不在初始化时给出假进度或固定完成时间。

每约 2 秒查询一次状态；离开面板停止轮询，任务继续。重新打开面板从服务读回状态，不靠 UI 内存恢复。

结果入口区分“处理完成，待导入”“已导入”“导入失败”和“局部文字层”。完成后提供“打开 OCR 副本”“显示质量报告”，不能只显示一个成功提示。

界面同时验证深色、浅色、窄窗口和高 DPI，不硬编码浅色背景；长文件名、错误内容和按钮不得重叠。

## 12. 建议代码改动清单

新增独立插件源码：

- `Zotero/tools/pdf-text-layer/manifest.json`、`bootstrap.js`、`prefs.js`：注册、生命周期与独立配置。
- `src/menus.ts`、`ui/ocr-dialog.*`、`ui/task-panel.*`：目标附件与任务交互。
- `src/attachment-adapter.ts`：身份、权限、输入快照与副本导入。
- `src/service-client.ts`、`src/runtime-discovery.ts`：服务发现、认证、轮询与版本握手。
- `src/derived-attachments.ts`：来源登记、去重和向侧栏提供桥接信息。

新增本地 Python 模块：

- `Zotero/ocr/core/engine.py`：RapidOCR 适配与模型版本。
- `page_classifier.py`、`geometry.py`、`text_writer.py`、`verification.py`：预检、坐标、写入及验收。
- `Zotero/ocr/service/models.py`、`store.py`、`supervisor.py`、`worker.py`、`api.py`：任务、租约、进程与接口。
- `Zotero/ocr/requirements.lock`、模型清单、安装/修复与停止脚本。

现有组件的有限改动：

- AI Sidebar 对应 0.8.18 源码：附件身份、选区上下文、相关缓存和 OCR 来源桥接；实际模块路径在 M0 找到源码后确认。打包 JS 中的函数名只能作为定位线索，不作为长期唯一补丁接口。
- `Start-Zotero.ps1`：保留既有翻译启动逻辑；增加 OCR 服务的幂等准备/发现入口，实际模型 worker 仅在有任务时启动。Zotero 从可执行文件直接启动时，插件也能发现或按固定入口启动服务。
- `install-manifest.json`、`使用说明.md`：记录真实构建版本、组件哈希、验收结果与回退方式。

不修改 DeepTutor 阅读路由、React 阅读器、知识库索引或现有 PDF2zh 公式保护。OCR 核心不导入 DeepTutor 包，方便将来被两个应用分别接入。

## 13. 分阶段实施与放行条件

### M0：当前安装与源码基线

备份当前插件、记录哈希、获取对应源码和构建方式，在独立测试配置目录验证升级/停用生命周期；核对历史分卷定制与 0.8.18 的差异。

放行条件：选区提问、DeepSeek/Qwen 联网、笔记、深色设置、分卷及 PDF2zh 公式保护均有可追溯基线。发现不一致先记录并修复必要前置问题，不擅自回滚当前插件。

### M1：样本 OCR 与隐藏文字内核

从实际《纳米材料》取第 16 页、连续正文页及表格/公式密集页；补旋转、CropBox、长行、中英混排、局部原生文字和空白页样本。比较 200/300 DPI。

放行条件：样本中文可搜索，正文与图注可分别选择，复制不截尾，字符和行框位置可用，旧原型越界问题已验证解决；相同渲染条件下可见页面不变。M1 不通过，不整书运行。

### M2：可恢复后台服务

实现持久任务、输入快照、单执行者、页检查点、取消和重试。

放行条件：10 页任务中途结束 worker 后可继续，已验证页不重复 OCR；损坏检查点被重做；取消只影响本任务；服务重启不会把旧任务误报为完成，也不自动重跑整书。

### M3：Zotero 插件与同条目导入

交付菜单、对话框、持久进度、深浅色界面、结果导入及打开副本。

放行条件：操作不需要聊天 AI；重复点击只导入一次；Zotero 关闭期间任务状态不丢；导入失败可重试；源附件哈希不变；只读库、独立附件、多个 PDF 和云端未下载附件均有明确行为。

### M4：AI 选段闭环与附件隔离

打开 OCR 版第 16 页，选正文、图注，进入侧栏解释与翻译；检查实际发送给模型的选区和附件页码，不以回复“看起来正确”作为唯一证据。

放行条件：无需先跑 MinerU；切换原件/完整 OCR/局部 OCR/另一份论文时不串选区、不串缓存；搜索、复制、高亮、加笔记与请求中的来源均指向当前 OCR 附件。日志只记录必要诊断，不泄漏 API Key。

### M5：全书、共存和发布

按实际读取页数处理当前教材，逐页生成检查结果；人工抽查正文、图注、公式、表格、章节边界及末页。演练一次中断续跑及导入恢复。

放行条件：请求页全部成功或按规则跳过，失败页清零后才发布全书成品；原书页数、顺序、页面几何、可见外观和结构得到验证。再次验证四个现有插件与 OCR 共存、启动和卸载。

开发排期在 M0–M1 后估算；整书 OCR 时间依据本机 10 页样本的实际阶段耗时估算，分别列出模型预热、识别、验证与导入，不承诺固定分钟数或未经测量的准确率。

## 14. 验收记录与交付物

验收报告至少包含：

1. 当前 Zotero、插件、OCR Python 包、模型及字体的版本和哈希。
2. 原附件 key、原/结果 SHA-256、真实页数、请求范围和导入后的附件 key。
3. 逐页分类、OCR/跳过/失败状态、框数量、未放置文字、越界和渲染对比结果。
4. 中文搜索词及命中页、多行复制样本、正文/图注选择截图与人工核查结果。
5. 第 16 页选段实际发送的文本、当前附件身份与 PDF 页序；无需 MinerU 的证明。
6. 取消、进程中断、服务恢复、重复提交与重复导入的结果。
7. 原附件批注、笔记、聊天及旧引用仍可访问的核对结果。
8. 其他插件回归、深浅色界面、重启、升级与回退测试。

最终交付包括：可维护源码、可安装 XPI、锁定环境与模型准备脚本、完整 OCR PDF、同条目附件、质量报告、用户说明和回退包。单页演示、聊天目录脚本或“模型已下载”均不算正式功能交付。

## 15. 回退与完成定义

发布前保留当前 0.8.18 及四插件完整备份、构建哈希和配置快照，采用独立配置目录先验收，随后再更新用户实际配置目录。

回退时停用 OCR 插件与其服务，恢复本次确实改过的 AI Sidebar 构建和启动脚本；不清空全部偏好，不覆盖 API 账号，不回滚整个 Zotero 数据库，不删除原附件或已导入的 OCR 成品。数据库备份如需恢复，必须作为另一个明确的数据恢复操作处理。

只有满足以下各项，才可宣布“当前 Zotero 已支持扫描课本添加文字层并选段问答”：

- 用户无需聊天协助，即可在 Zotero 中启动、查看、取消、继续和打开结果。
- OCR 版确实作为同一文献的独立附件保存，原件未覆盖。
- 在 Zotero Reader 内可选择、复制、搜索、高亮，且位置与原扫描内容相符。
- AI 侧边栏实际接收到该 OCR 附件的选区与正确页码，不受全书 MinerU 页数限制阻塞。
- 请求范围全部通过验证，完整教材有可追溯的逐页报告。
- 旧批注、原阅读状态、已有翻译、联网与深色模式未被本功能破坏。
